Launch checklist

Install the operator, then apply the network charter.

The first-run path stays simple: install FabricOps into a cluster, apply a FabricNetwork, then wait for the operator to publish a ready network and client material.

install.yaml 
kubectl apply -f https://github.com/LF-Decentralized-Trust-labs/FabricOps/releases/download/v0.2.0/install.yaml
kubectl rollout status deployment/fabricops-controller-manager -n fabricops-system --timeout=120s
fabricops-0.2.0.tgz 
helm upgrade --install fabricops \
  https://github.com/LF-Decentralized-Trust-labs/FabricOps/releases/download/v0.2.0/fabricops-0.2.0.tgz \
  --namespace fabricops-system \
  --create-namespace \
  --wait
fabricnetwork-sample 
kubectl apply -f https://raw.githubusercontent.com/LF-Decentralized-Trust-labs/FabricOps/v0.2.0/config/samples/fabricops_v1alpha1_fabricnetwork.yaml
fabricopsctl wait -n default --timeout 20m fabricnetwork-sample
fabricopsctl connection-profile -n default --org BankA --format yaml fabricnetwork-sample
receipt / 0001

What ready means

  • Fabric CA registrar bootstrapped
  • Admin, peer, and orderer identities enrolled
  • Managed MSP/TLS certificates valid or renewing
  • Orderers and peers joined declared channels
  • CCaaS packages installed, approved, committed, and served
  • Operations endpoints and connection profiles exposed

Operator blueprint

The CR is a contract. The cluster becomes the evidence.

FabricOps makes the Kubernetes objects and Fabric actions traceable back to the manifest that requested them. That is the operational difference between a demo network and an infrastructure control plane.

intent fabricnetwork.yaml 
spec:
  global:
    fabricVersion: "3.1.0"
    tls: true
  orgs:
    - organization:
        name: BankA
        mspName: BankAMSP
      peer:
        instances: 2
        db: CouchDB
  channels:
    - name: settlement

Organization charters

Each organization gets a runtime boundary with a public identity.

Per-org namespaces keep ownership legible. The operator can still reason about one network while each organization carries its own CA, identity material, storage, and workload surface.

CCaaS assembly lane

Chaincode is not just deployed. It is installed into the network.

FabricOps treats Chaincode-as-a-Service as lifecycle infrastructure: package metadata, package IDs, peer installs, org approvals, channel commit, runtime deployment, and upgrades.

01

Package

Generate peer-specific connection metadata.

02

Install

Run Fabric tools Jobs for selected peers.

03

Approve

Submit org approvals once package IDs are known.

04

Commit

Commit channel definitions with policy satisfied.

05

Serve

Deploy CCaaS workloads at the address peers expect.

Federated joining

A network can grow across clusters without losing its audit trail.

Banks and regulated organizations often need to own their own infrastructure. FabricOps models that reality with founder-side admission and participant-owned FabricParticipant resources.

Founder

FabricNetwork

Exports public MSP roots, orderer endpoints, channel hints, and signer requirements.

join bundle MSP roots endpoints policies
Participant

FabricParticipant

Imports channel artifacts, reconciles local peers, installs chaincode, and participates in endorsement.
